# Proposal

## Why

A sales manager receives raw sales exports as CSV files and needs a fast, trustworthy read of regional and branch performance, the weakest outlets, and a plain-English summary they can forward. Today that means manual spreadsheet work. A small self-contained web app turns an uploaded CSV into that report in seconds, with no server, no install, and no data leaving the browser.

## What Changes

- Add a static, browser-only web app built from ES modules in Vanilla JavaScript (no runtime dependencies) with a Vite dev/build toolchain; the app runs entirely in the browser with no backend.
- Add CSV ingestion with flexible schema binding: read the file's own header row, auto-detect columns by name and synonyms, and show a **column mapping panel** the user confirms before any processing. Required fields (region, outlet id, net sales) must be mapped; optional fields degrade gracefully.
- Add a sales dashboard: net sales by region (with share), branch breakdown, and the five lowest-selling outlets ranked by absolute net sales, each tagged by severity relative to its region average (CRITICAL / LOW / BELOW / OK).
- Add a manager-oriented one-paragraph summary generated by a **guarded-clause template** (no LLM, no network): every clause is emitted only when its condition holds, so the wording never asserts something the data does not support.
- Add message delivery with no server: **Copy** the summary and **Send via Telegram** (opens Telegram with the text prefilled via `t.me/share`). No bot token or chat id is used, since a browser cannot call the Telegram Bot API safely.
- Add explicit handling for dirty and limited data: CSV faults are reported as the file's problem with a fix instruction; valid-but-limited data (single month, fewer than five outlets, no critically weak outlet, negative totals) adapts the display and guards the summary.
- No region normalization: regions are grouped by the exact string in the file. Cleaning the data is the user's responsibility.
- Add automated tests (Vitest + jsdom) targeting 100% coverage of the app's JavaScript, wired as a GitHub Actions CI gate on push and pull request.

## Capabilities

### New Capabilities
- `csv-ingestion`: upload a CSV, read and auto-detect its columns, present a confirmable column mapping, validate required fields, and parse rows while reporting file faults clearly.
- `sales-analytics`: aggregate parsed rows into region and branch totals, compute outlet performance and severity tiers, and render the dashboard and weakest-outlet view with edge-case handling.
- `manager-summary`: generate the guarded-clause plain-English paragraph and deliver it via copy-to-clipboard or a prefilled Telegram share.

### Modified Capabilities
- None. This is a new project with no existing specs.

## Impact

- New files: `index.html`, `src/` (pure logic modules plus a thin DOM/UI layer), `test/`, `vite.config.js`, `vitest.config.js`, `package.json`, and `.github/workflows/test.yml`. No backend, no database, no runtime dependencies; the only dev dependencies are Vite, Vitest, and jsdom.
- Reads the user-selected CSV locally; no data is transmitted anywhere except when the user chooses to share the summary through Telegram.
- Reference data: `sales.csv` in the project root is the sample format and test input.
